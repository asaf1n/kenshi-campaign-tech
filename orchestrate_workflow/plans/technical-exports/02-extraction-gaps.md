# 02-extraction-gaps

## Цель

Конвертер извлекает и кэширует в структурированном виде данные, которых нет для табличных выгрузок: базовые цены предметов, торговые коэффициенты, записи World States / Town Overrides с условиями и эффектами, склады со строками «поселение, здание, контейнер, предмет, количество».

## Решения

- 2026-11-05. Источник чисел — файлы игры и сейв, читаются только на чтение; новое извлечение расширяет `tools/gamedb.py` и `tools/player_assets.py`/`world_context.py`, новых зависимостей нет. Предложение.
- 2026-11-05. Базовая цена — значение `int.value` записи ITEM после слияния модов в порядке загрузки (`gamedb.build`); пример: пенька 50 в `gamedata.base`, 100 после `rebirth.mod`. Указывать итоговое значение и файл-источник. Проверено чтением записей.
- 2026-11-05. Условия реакций выгружаются «как хранятся»: тип записи, имя, `bool/int/float/string`, `refs` со значением `v` (например `NPC is` → `[1,0,0]`), без трактовки. Числовые типы 52, 110, 104, 51, 27 не имеют имён в `gamedata.po`; фиксируется соответствие из чтения записей в `docs/data-contract.md`. Предложение.

## Этапы задачи

1. Разведка форматов (чтение, без изменения продукта). Для World State (тип 110), Town Override (TOWN с «(override)»), записей 52 и `ITEMS_CULTURE` (104, `trade prices`) выписать поля и связи на реальных файлах `rebirth.mod`, `Dialogue.mod`, `RU Reactive World.mod`/`LivingWorld.mod`; определить, как world state из `usedUniques` сейва (sid + `state_code`) связан с записями условий и с override-ами городов; определить источник торговых коэффициентов города и культуры. Готово: в `result.md` таблица «поле → запись → пример значения» по каждой группе и список полей, которые найти не удалось (с указанием, что не публикуется). Не начат.
2. Индекс игры. Поднять `INDEX_VERSION` до 9: `value` в ITEM, `buy mult`/`sell mult`/`price mod`, ссылки `trade prices`; добавить функцию выборки записей реакций с `refs[...]['v']` из `db["records"]` (без раздувания кэша `gamedb_*.json`: отдельный кэш записей реакций). Готово: индекс пересобирается детерминированно (два запуска дают одинаковые файлы кэша); `python -m unittest tests.test_gamedb` проходит; пенька и гашиш имеют цену; размер нового кэша указан в отчёте. Не начат.
3. Склады. Строки склада строятся из `buildings[].storage` и вложенного `interior`: поселение берётся из `locations.json` (`building_key`), здание — `name`/`template`, контейнер — идентификатор записи; исправить `aggregate_storage_by_location`, чтобы имена предметов не заменялись SID, а ключами служили названия поселений при `in_location`/`near_location` (зона — запасной ключ с пометкой). Готово: на снимке 06:03 пенька = 434 / 264 / 5 для Деревни Серодёров / Ровной лагуны / Скуина, гашиш в лагуне = 1; сумма строк равна `total_items_count` по зоне; здания без поселения перечислены явно. Не начат.
4. Отряд и экипировка. Проверить наличие `lost_limbs`, `quality` экземпляров, слота для носимых предметов; добавить недостающие поля в снимок только при наличии источника (иначе пометка «недоступно» в словаре колонок). Готово: для Зелёного пальца видны протез «Нога разведчика (левая)» level 95, грейд «Мастерский», 3 оружия Катун и пять Мейто в `weapons`; список недоступных полей приложен. Не начат.
5. Регрессия. Тесты: цена предмета по порядку модов (табличный, на мини-моде из `tests`-фикстур), строки склада с поселением и без. Готово: два теста, каждый ловит конкретную ошибку (подмена цены ранним файлом; потеря предметов при пустом `town`); `python -m unittest discover -s tests` и `python tests/run_evidence.py` проходят. Не начат.

Зависимости: нет входных; результат нужен задаче 03. Риски: этап 1 может показать, что торговые коэффициенты города не хранятся в gamedata (зависят от типа здания/культуры) — тогда `trade_modifiers.csv` публикует только найденные поля; пересборка индекса — минуты и требует установленной игры (путь `KENSHI_DIR`).
