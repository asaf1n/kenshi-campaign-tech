# mvp-pipeline

Статус плана: утверждён 2026-11-01

Цель плана: реализовать единый локальный воспроизводимый конвейер `extract → normalize → resolve_locations → diff → validate → render → publish`, переиспользующий `kenshi-platoon-export`, извлекающий версионированный справочник мира из установленной Kenshi и активных модов, пространственно разрешающий локации персонажей и построек без догадок, сохраняющий исходные сейвы и публикующий подтверждённое состояние кампании для ChatGPT; выполнить P0 из [требований](../../../docs/requirements.md) и подтверждённое географическое расширение (включённое в план отдельной задачей перед P0-задачами веток и e2e по дополнительному заданию пользователя от 2026-11-01 о проверке и интеграции географических данных) с доказательствами по [AC-01..AC-15](../../../docs/acceptance.md), без параллельного pipeline, отдельного проекта или альтернативного manifest.

Исходная версия: `cc89b81` (`cc89b812a08f6d9552fe70260cea29df2d91d269`); в рабочем дереве присутствует только неотслеживаемый `orchestrate_workflow/plans/`. План составлен и пересмотрен 2026-11-01. Инвентаризация конвертера выполнена чтением исходников и существующего JSON конвертера; первичные ресурсы мира в установленной Kenshi `1.0.68 - x64 (Newland)` (`leveldata.level`, `areasmap.tga`, `gamedb`) и аудит внешнего прототипа `kenshi_world_grid_bundle` зафиксированы по внешнему наблюдению оркестратора от 2026-11-01; сквозная обработка реальных сейвов проектным конвейером и доступ ChatGPT в рамках планирования не проверялись.

Задачи и их этапы выполняются строго последовательно (`1.1 → 1.2 → 2.1 → 2.2 → 3.1 → 3.2 → 4.1`). Следующий этап начинается после приёмки предыдущего; общие схемы, справочник мира, индекс и публикация имеют одного исполнителя. Независимое ревью плана и утверждение пользователя предшествуют отдельному запуску реализации по [привязке workflow](../../method.md). Эта очередь не утверждает план и не разрешает запуск.

Границы: Python и файлы; существующие `kenshi-session/10`, `kenshi-session-diff/5`, проектные `kenshi-publication/1`, `kenshi-world-reference/1`, `kenshi-locations/1` и `kenshi-event/1`. Новый бинарный парсер GameData с нуля, сервер, БД, веб-интерфейс, обращение к внешним веб-картам в runtime и LLM в runtime не требуются (`kenshi_gd` и `gamedb` переиспользуются read-only). Конвертер и установленная игра подключаются через конфигурацию и остаются внешними read-only источниками. Исходные сейвы, сырые бинарные файлы/текстуры игры и модов, скриншоты и персональные настройки не включаются в Git. Push и изменение внешних разрешений — только по отдельному указанию.

Распределение требований и соответствие при пересмотре очереди: извлечение, идентичность, совместимый diff и базовый выпуск с заделом схемы `manifest.json` под географические артефакты — задача [01-vertical-slice](01-vertical-slice.md) (этапы `1.1`, `1.2`, без перенумерации); версионированный справочник мира из игры/модов, пространственное разрешение локаций персонажей и построек, группы близости, геометрическое смещение и интеграция гео-сводок в единую публикацию — новая задача [02-world-geography](02-world-geography.md) (этапы `2.1`, `2.2`); родительство, reload, блокировка ложных перемещений между ветками, события и игровые сессии — задача [03-branches-and-timeline](03-branches-and-timeline.md) (этапы `3.1`, `3.2`; перенесена из прежней `02-branches-and-timeline`, прежние этапы `2.1`, `2.2`); реальные доказательства на сейвах, канал ChatGPT, Windows-инструкция и итоговая приёмка — задача [04-e2e-verification-and-ops](04-e2e-verification-and-ops.md) (этап `4.1`; перенесена из прежней `03-e2e-verification-and-ops`, прежний этап `3.1`). Точные критерии и зависимости находятся в материалах задач, без копирования этапов в очередь.
