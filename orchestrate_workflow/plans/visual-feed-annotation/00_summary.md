# visual-feed-annotation: Автоматическая разметка визуальной ленты скриншотов Kenshi

Статус плана: выполнено

## Цель плана
Обеспечить игрового компаньона (LLM-ассистента) контекстом происходящих в Kenshi событий без ручного описания скриншотов игроком.
Обработчик анализирует изображения за скользящее 7-дневное окно, извлекает видимую информацию (OCR интерфейса, диалоги, локации, участники, тип сцены), выполняет двухуровневую дедупликацию (точные дубли по SHA-256 и группировка похожих кадров одной сцены по dHash/таймингу), формирует машиночитаемый индекс `annotations.jsonl` и хронологическую ленту сцен `feed.md`, интегрируясь в существующий конвейер публикации `published/screenshots/`.

## Инварианты и архитектурные границы
1. **Read-only входные данные**: Исходный каталог `_screens` и сейвы игры строго read-only. Никаких модификаций оригиналов.
2. **Изоляция сбоев**: Сбой анализа изображений или внешнего API разметки ни при каких обстоятельствах не блокирует публикацию проверенных числовых данных сейва и оригинальных скриншотов (graceful degradation).
3. **Кэширование по SHA-256**: Неизмененные кадры не обрабатываются повторно. Повторный запуск конвейера детерминирован и бесплатен по ресурсам.
4. **Машинные наблюдения != игровая хроника**: Разметка фиксирует строго наблюдаемые факты (с пометкой provenance и confidence), не придумывает скрытые события и не подменяет числовое состояние конвертера.
5. **Сохранение существующих контрактов**: `index.json` (`kenshi-screenshots-index/1`), `index.md` и оригинальные файлы скриншотов сохраняются без нарушения обратной совместимости.
