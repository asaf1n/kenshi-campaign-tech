# 03-published-payload-optimization

## Цель

Оптимизировать структуру и объем артефактов каталога `published/`, устранить дублирование между Markdown-отчетами и CSV-таблицами, сжать `brief.md` до 3–5 КБ (оставив только то, чего нет в таблицах), запланировать снятие `squad.md` при полном покрытии через `squad.csv`, создать компактное оглавление `tables/index.md` со словарями колонок `tables/dict/<таблица>.md` для неочевидных витрин, исключить ссылки на крупногабаритные технические JSON (`extended/current.json`, `unique_entities_registry.json`, `world_reference.json`) из навигационного пути LLM с переадресацией на компактные CSV-витрины, сохранив при этом канонические пути файлов в корне `published/` для стабильности конвейера доставки, картографии и веб-карты.

## Решения

- 2026-11-12. Аудит и ревью плана: отказаться от физического переноса файлов `world_reference.json` и `unique_entities_registry.json` в подкаталог `internal/`. Сохранить их канонические пути на верхнем уровне `published/` для гарантированной совместимости с `tools/cartography.py`, `tools/deliver_companion.py` и просмотрщиком карты `sites/map/index.html` в Kenshi-Compain.
- 2026-11-12. Корректировка по ревью: оптимизацию объема контекста для GitHub-коннектора Custom GPT выполнить на уровне навигации и структуры документов:
  1) сжать `brief.md` в `tools/rendering.py`: оставить шапку выпуска (кампания, идентификатор снимка и родителя, признак перезагрузки, игровое время), казну, численность отряда по игровым отрядам и по пространственным группам, счётчики изменений и карту витрин со ссылками на CSV. Ролей, отбора «ключевых» отношений и пересказа событий в `brief.md` нет: роли ведёт компаньон, отношения целиком лежат в `tables/diplomacy.csv`, события — в `changes.md`;
  2) полностью исключить ссылки на тяжелые машинные JSON (`world_reference.json`, `unique_entities_registry.json`, `extended/current.json`) из `brief.md`, адресовав компаньона к компактным витринам `tables/unique_entities.csv` и оглавлению `tables/index.md`;
  3) снятие `squad.md`: подтвердить, что `squad.csv` полностью заменяет `squad.md` по всем полям; запланировать безопасное снятие `squad.md` (удаление генерации и из манифеста) после сверки полноты полей, чтобы не расходовать лимиты контекста модели на дубли;
  4) оглавление `tables/index.md`: создать компактное оглавление со списком всех CSV, их кратким назначением, ключевыми полями соединения и числом строк;
  5) словари колонок `tables/dict/<таблица>.md`: вынести описания колонок в отдельные файлы для каждой таблицы без исключений (по одному файлу на CSV): словарь колонок — контракт для модели, включая единицы, коды и правила `calc_*`. Содержание словарей переносится из текущего `tables/index.md` без потерь; модель подгружает файл нужной таблицы.
