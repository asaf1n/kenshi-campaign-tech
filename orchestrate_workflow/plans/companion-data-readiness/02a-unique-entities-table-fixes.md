# 02a-unique-entities-table-fixes

## Цель

Устранить дефекты витрины `published/tables/unique_entities.csv`, найденные внешним ревью выпуска `sha256-ac77d739` (Day 136 20:21), и передать формат ручного слоя для протокола компаньона. Выполняется до задачи 03.

## Решения

- 2026-11-12. Ревью выпуска: колонка `cleared` равна `false` у всех 164 строк боссов, хотя у 10 боссов в `unique_entities_registry.json` заполнено `static_locations[].cleared_evidence` (пример: Великий шаман, `26-rebirth-INGAME`). Витрина читает поле верхнего уровня записи, которое всегда пусто. Значение брать из связей с локациями.
- 2026-11-12. Ревью выпуска: колонку `cleared` переименовать в `location_cleared` и описать как «место персонажа отмечено зачищенным». Зачистка места и исход для персонажа — разные факты: исход отражают `state_code` и `outcome`. Формулировку «признак зачистки/победы» из словаря колонок убрать. Для персонажа с несколькими местами значение `true`, когда зачищено основное место (`primary_location_instance_id`); при `location_resolution = ambiguous` значение пустое.
- 2026-11-12. Ревью выпуска: 164 персонажа представлены двумя строками с одним `sid` (`entity_kind = npc` и `entity_kind = boss`). Оставить одну строку на `sid`: `entity_kind` принимает значения `npc` и `meitou`, принадлежность к боссам и лидерам передаёт `category`. Итог: 236 строк персонажей и 26 строк Мейто.
- 2026-11-12. Синхронизация с `Kenshi-Compain`: отправить накопленные коммиты в `origin main` и приложить к отчёту точный формат `entities_progress.json` — путь к схеме и эталонному примеру, допустимые значения `outcome`, правило сопоставления `sid`. Протокол `[итог]` компаньона обновляет сессия настройки по этим данным; до этого файл в `Kenshi-Compain` не создаётся.
