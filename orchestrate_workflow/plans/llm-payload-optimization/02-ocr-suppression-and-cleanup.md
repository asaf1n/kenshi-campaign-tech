# 02-ocr-suppression-and-cleanup: Подавление пустых OCR-артефактов

## Цель
Устранить неоправданный расход контекста LLM (~235 тыс. токенов) на пустые OCR-выгрузки. При отсутствии содержательного текста интерфейса не публиковать `feed.md`, `index.md` и `annotations.jsonl`, оставляя только компактный `index.json`, и очищать устаревшие артефакты при доставке.

## Решения
- 2026-11-03. В текущем релизе OCR распознал 0 из 343 кадров (`provenance.source = metadata`), породив 4 избыточных представления почти без смысловой информации.
- 2026-11-03. Содержательность OCR оценивается по полному набору полей контракта `ocr` (`tools/screenshot_extractor.py:207`): `dialogues`, `characters`, `location`, `game_day`, `game_time`, `notifications`, `items_or_tasks`. Если во всех кадрах выпуска каждое из этих полей пусто (`None`, `[]`, `""`), выпуск считается не содержащим распознанного текста. Наличие даже изолированного распознанного дня (`game_day`) или времени (`game_time`) считается содержательным результатом и сохраняет публикацию ленты.
- 2026-11-03. При полностью пустом OCR публикатор подавляет генерацию `feed.md`, `index.md` и `annotations.jsonl`, а также исключает опциональные ключи `screenshot_annotations` и `screenshot_feed` из `manifest.json["artifacts"]`.
- 2026-11-03. Утилита доставки `deliver_companion.py` дорабатывается: при синхронизации каталога `screenshots/` удаляются файлы, отсутствующие в текущей публикации, гарантируя очистку устаревших артефактов в `Kenshi-Compain`.
- 2026-11-03. Синхронно обновляются `docs/data-contract.md` и `docs/architecture.md`.

## Этапы задачи

1. **Критерий содержательности OCR и подавление публикации (`tools/publisher.py`, `docs/data-contract.md`)**. Реализовать проверку всех полей `ocr` (`dialogues`, `characters`, `location`, `game_day`, `game_time`, `notifications`, `items_or_tasks`). При нулевом содержательном выходе исключать `feed.md`, `index.md`, `annotations.jsonl` из публикации и из `manifest.json["artifacts"]`. Готово: при пустом OCR файлы разметки не создаются, `index.json` публикуется в минимальном виде. Не начат.
2. **Очистка устаревших артефактов при доставке (`tools/deliver_companion.py`)**. Добавить в `deliver_companion.py` удаление из целевого каталога `published/screenshots/` файлов, отсутствующих в исходной публикации (`annotations.jsonl`, `feed.md`, `index.md`). Готово: доставка в `Kenshi-Compain` удаляет неактуальные артефакты. Не начат.
3. **Регрессионные тесты и валидация (`tests/test_screenshot_annotations.py`, `tests/test_screenshots.py`, `tests/test_publish.py`)**. Покрыть сценарий подавления пустых артефактов тестами (включая проверку сохранения разметки при наличии только `game_day`/`game_time`) и проверить валидацию манифеста. Готово: тесты проходят. Не начат.
