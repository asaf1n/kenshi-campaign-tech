# 02-ocr-suppression-and-cleanup: Подавление пустых OCR-артефактов

## Цель
Устранить неоправданный расход контекста LLM (~235 тыс. токенов) на пустые OCR-выгрузки. При отсутствии распознанного текста на скриншотах не публиковать `feed.md`, `index.md` и `annotations.jsonl`, оставляя только компактный `index.json`.

## Решения
- 2026-11-03. В текущем релизе OCR распознал 0 из 343 кадров (`provenance.source = metadata`), породив 4 избыточных представления почти без смысловой информации.
- 2026-11-03. Схема `contracts/manifest.schema.json` определяет `screenshot_annotations` и `screenshot_feed` как опциональные поля в `artifacts`. При отсутствии полезных данных разметки они исключаются из манифеста и не генерируются на диск.
- 2026-11-03. Починка OCR или интеграция внешнего Vision API выносится в отдельную изолированную задачу; до ее решения действует строгий fallback-режим «только компактный `index.json`».

## Этапы задачи

1. **Модификация логики публикации (`tools/publisher.py`)**. Добавить проверку качества OCR: если ни один кадр не содержит распознанного текста (`dialogue`, `names`, `location_text` пустые), подавлять запись `feed.md`, `index.md` и `annotations.jsonl`. Исключать соответствующие ключи из `manifest.json["artifacts"]`. Готово: при отсутствии OCR файлы разметки не создаются, `index.json` остается минимальным. Не начат.
2. **Коррекция валидатора публикации (`tools/validation.py`)**. Проверить, что валидатор `validate_publication` корректно обрабатывает отсутствие опциональных `screenshot_annotations` и `screenshot_feed` в `manifest.json["artifacts"]`. Готово: `validate_publication` проходит без ошибок. Не начат.
3. **Регрессионные тесты (`tests/test_screenshot_annotations.py`, `tests/test_screenshots.py`)**. Убедиться, что тесты покрывают сценарий подавления пустых артефактов без сбоев конвейера. Готово: тесты проходят. Не начат.
