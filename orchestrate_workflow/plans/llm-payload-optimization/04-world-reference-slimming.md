# 04-world-reference-slimming: Облегчение справочника мира

## Цель
Сократить размер справочника `published/world_reference.json` с 650 тыс. символов до семантического минимума (<220 тыс. символов, сокращение ~68%), исключив из публикуемой проекции тяжелый RLE-растр `regions_map` (420 тыс. символов) и исходные контрольные суммы `source_hashes` (81 тыс. символов), сохранив неизменяемый полный кэш в `data/world/` для инженерных утилит.

## Решения
- 2026-11-03. Для LLM растровый массив `regions_map` (65536 значений RLE) и хэши исходников `source_hashes` не несут пользы и перегружают контекст. Моделям необходимы семантические описания: регионы, биомы, опасности, города, фракции. Исключение обоих блоков сокращает размер файла с ~650k до ~203k символов (~68% экономии).
- 2026-11-03. Инженерный локатор (`tools/locator.py`) производит пространственное разрешение зон по полному объекту справочника, передаваемому аргументом из `data/world/` (`DEFAULT_WORLD_DIR`), не завися от публичного файла.
- 2026-11-03. Облегчение оформляется как публикационная проекция: полный файл сохраняется в неизменяемом хранилище `data/world/` по `world_ref_id`, а в `staging` при каждой сборке пакета публикации выгружается облегченная семантическая часть `world_reference.json`. В схеме `contracts/world-reference.schema.json` поля `regions_map` и `source_hashes` делаются опциональными.
- 2026-11-03. Синхронно обновляются `docs/data-contract.md` и `docs/architecture.md`.

## Этапы задачи

1. **Публикационная проекция справочника мира (`tools/publisher.py`)**. Реализовать формирование проекции для публикации: исключение `regions_map` и `source_hashes` при записи `published/world_reference.json` в staging. Полный файл в `data/world/` остается без изменений. Готово: объем `published/world_reference.json` составляет <220 тыс. символов. Не начат.
2. **Адаптация схемы и валидатора (`contracts/world-reference.schema.json`, `tools/validation.py`, `docs/data-contract.md`)**. Сделать поля `regions_map` и `source_hashes` опциональными в схеме `contracts/world-reference.schema.json`. Обновить валидатор `validate_world_reference`, чтобы он проверял RLE-сегменты только при их наличии в объекте. Готово: валидация опубликованного справочника проходит успешно. Не начат.
3. **Изоляция и тесты локатора (`tools/locator.py`, `tests/test_locations.py`)**. Убедиться, что `tools/locator.py` получает полный справочник из `data/world/` и сохраняет точность пространственной привязки зон. Готово: тесты `tests/test_locations.py` проходят. Не начат.
