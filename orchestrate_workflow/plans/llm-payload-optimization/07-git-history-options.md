# 07-git-history-options: Анализ и подготовка вариантов оптимизации git-истории

## Цель
Подготовить для игрока взвешенное техническое предложение по оптимизации размера git-хранилища игрового репозитория `Kenshi Compain`.
На текущий момент каталог `.git/objects/pack` в `Kenshi Compain` занимает ~174 МБ из-за однократно закоммиченных 343 несжатых скриншотов. Текущие оптимизации конвертера предотвращают дальнейший рост будущих коммитов, но уже зафиксированные в истории объекты автоматически не уменьшаются.

> [!WARNING]
> **Стоп-условие 3**: Любые операции перезаписи истории git (squash, rebase, filter-repo) и `git push --force` производятся СТРОГО по прямому явному указанию игрока. Эта задача носит исключительно аналитический характер (подготовка вариантов и последствий).

## Варианты решения для игрока

### Вариант 1: Оставить историю как есть (Консервативный, без рисков)
- **Суть**: В `origin/main` сейчас находится ровно 1 коммит (`88c9268`, объем архива 174 МБ). Локальный репозиторий сохраняет текущую историю. Новые коммиты добавляют только легковесные keyframes (по ~150 КБ).
- **Плюсы**: Нулевой риск расхождения веток, полная прозрачность git log, отсутствие необходимости force-push.
- **Минусы / Компромисс**: Клонирование репозитория продолжит скачивать 174 МБ. Gemini Web UI импорт всего репозитория целиком будет заблокирован (лимит 100 МБ), доступен только выборочный импорт файлов или использование `chat-pack/`.

### Вариант 2: Сжатие локальной истории в 1 коммит до первого push (Рекомендуемый)
- **Суть**: Поскольку в удаленный репозиторий `origin/main` отправлен только начальный коммит, а наработки компаньона еще не пушились: пересоздать коммит публикации снимка Day 131 с уже оптимизированными скриншотами (или исключить тяжелые кадры из корня коммита).
- **Плюсы**: Размер репозитория падает со 174 МБ до <40 МБ. Импорт в Gemini полностью разблокируется.
- **Минусы / Риски**: Требует согласования и одного `git push --force-with-lease` поверх начального коммита.

### Вариант 3: Очистка через git filter-repo / git-lfs (Хирургический)
- **Суть**: Применение `git filter-repo --path published/screenshots/ --invert-paths` либо перевод скриншотов в LFS / внешний storage.
- **Плюсы**: Полная очистка git blob при сохранении структуры коммитов.
- **Минусы / Риски**: Ломает все существующие SHA коммитов, требует переклонирования для всех внешних клиентов. Избыточная сложность для однопользовательской кампании.

## Результат задачи
Сформированный документ сопоставления вариантов для демонстрации игроку в точке остановки. Решение принимает игрок.
