# 07-git-history-options: Анализ и подготовка вариантов оптимизации git-истории

## Цель
Подготовить для игрока взвешенное предложение по размеру git-хранилища репозиториев `Kenshi-Compain` и `kenshi-campaign-tech`. Выгрузка больше не публикует тяжёлые скриншоты (этапы 01-03), но уже зафиксированные в истории объекты автоматически не уменьшаются.

> [!WARNING]
> **Стоп-условие 3**: любая перезапись истории (filter-repo, orphan-коммит, rebase) и `git push --force` выполняются СТРОГО по прямому указанию игрока. Задача аналитическая.

## Состояние на 2026-11-03
- Оба репозитория публичные на GitHub; `origin/main` содержит историю (в Kenshi-Compain около двадцати коммитов за этот день).
- `.git`: Kenshi-Compain ~180 МБ (pack 173,6 МиБ плюс свежие незапакованные объекты), kenshi-campaign-tech ~180 МБ (pack 178,8 МиБ). Основной объём — 343 скриншота 2880x1800 (~187 МБ) в первом коммите `88c9268` Kenshi-Compain и в ранних коммитах выгрузки tech.
- Рабочее дерево Kenshi-Compain: `published/` ~6,5 МБ (30 ключевых кадров, шарды `current/`, `extended/current.json`).
- Инструмент `git filter-repo` на этой машине не установлен (`pip install git-filter-repo`).

## Варианты

### Вариант 1: оставить историю (нулевой риск)
- Новые коммиты малы (кадры по ~150 КБ, шарды единицы КБ). Клон по-прежнему скачивает ~180 МБ. Инструменты, импортирующие репозиторий целиком с лимитом 100 МБ, не справятся; выборочная загрузка файлов и чтение по ссылкам работают.
- Без force-push; история и SHA-хэши сохраняются.

### Вариант 2: удалить тяжёлые файлы из всей истории через `git filter-repo` (рекомендуется)
- `git filter-repo --path published/screenshots --invert-paths` (для tech дополнительно устаревшие выгрузки с кадрами) удаляет только каталог скриншотов из всех коммитов; сообщения и остальное содержимое сохраняются, SHA-хэши меняются.
- Размер `.git` падает примерно до 5-10 МБ. Нужен один `git push --force-with-lease origin main` в каждом репозитории; открытые клоны и ссылки на старые SHA перестанут совпадать (однопользовательский репозиторий, внешних клонов нет).
- Требует установки `git-filter-repo` и резервной копии (`git clone --mirror`).

### Вариант 3: новая история одним коммитом (orphan)
- Состояние дерева сохраняется, история обнуляется; размер минимален. Теряются сообщения коммитов и история правок канона, `Co-Authored-By` и атрибуция прошлых изменений. Так же нужен force-push.
- Имеет смысл, только если история правок канона не нужна.

Git LFS не нужен: тяжёлые файлы из публикации убраны, а новые кадры не превышают нескольких МБ на выпуск.

## Результат задачи
Документ для решения игрока. До его указания история не изменяется.

## Выполнено для Kenshi-Compain (2026-11-04, по указанию игрока)
- Вариант 2 применён к `Kenshi-Compain`: `git filter-repo --path-regex '^published/screenshots/screenshot_[0-9]+\.jpg$' --invert-paths` в свежем клоне, затем `git push --force-with-lease` (старая голова `8c5f0bc`, новая `44dcf44`).
- Результат: `.git` 179 МБ -> 7 МБ, коммитов 22, деревья старой и новой голов совпадают (0 различающихся файлов). Резервное зеркало до перезаписи: `compain-backup.git` в рабочем каталоге сессии вне проекта.
- `kenshi-campaign-tech` не изменялся: решение игрока относилось только к Kenshi-Compain.
