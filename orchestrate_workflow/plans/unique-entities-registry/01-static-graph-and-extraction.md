# 01-static-graph-and-extraction

## Цель

Обеспечить извлечение недостающих звеньев статического графа связей и идентификаторов в GameDB и сохранении:
1. В `tools/gamedb.py`:
   - Расширить чтение записей типа `TOWN` (тип 13): сохранять категории ссылок `residents` (отряды-резиденты, где находятся боссы и уникальные NPC), `bar squads` (отряды в барах с рекрутами) и `spawns`, а также скалярные поля городов.
   - Обеспечить доступность входящих ссылок `TOWN -> SQUAD_TEMPLATE -> CHARACTER` в структурах `records["units"]` / вспомогательном индексе размещения отрядов.
   - **Инвалидация кэша GameDB**: инкрементировать версию кэша в `tools/gamedb.py` (константу версии `INDEX_VERSION` / префикс `data/cache/gamedb_records_*`), чтобы существующий кэш автоматически инвалидировался и пересобирался с полным графом без ручного удаления файлов.
2. В `tools/save_reader.py` и `tools/converter_worker.py`:
   - Включить `template_sid` (извлекаемый в `save_reader.parse_character` L860 из записи типа 30 `.platoon`) в итоговый словарь персонажа `characters[]` снимка `current.json` (через кортеж пробрасываемых полей в `converter_worker.py` L65).
3. В `tools/world_context.py`:
   - Реализовать детерминированное связывание `world_state.unique_npcs` с `characters` отряда игрока по строгому равенству валидных полных кортежей `handle: [TYPE, C, S, I, CS]`.
   - **Правило валидации handle**: список из 5 элементов считается пригодным для сопоставления только если все 5 элементов являются `int` (не `None`) и хотя бы один элемент не равен 0 (по правилу `_clean_handle_tuple`). Любое неполное значение (содержащее `None` или состоящее из всех нулей) отбрасывается как непригодное для сопоставления и переводит статус связи в `unresolved`, исключая ложные совпадения `None == None`.

## Решения

- 2026-11-11. Эмпирически доказано: флаг `usedUniquesPlayer` в Kenshi равен `True` для поверженных/захваченных боссов, а для нанятых в отряд рекрутов равен `False`. Единственный детерминированный способ подтверждения нахождения уникального NPC в отряде игрока — сверка `unique_npcs[].handle` с `characters[].handle` (подтверждено на 26 рекрутах кампании).
- 2026-11-11. Эмпирически доказано: связь уникальных NPC с городами в GameDB задается через `TOWN.refs["residents"]` (например, `48447-rebirth.mod -> 50569-rebirth.mod -> 50570-rebirth.mod` для Ожога; `50522-rebirth.mod -> 50521-rebirth.mod -> 50519-rebirth.mod` для Великого шамана; `95726-rebirth.mod -> 96404-rebirth.mod -> 96409 / 96407 / 96412 -> 97095` для Башни Жестокости).
- 2026-11-11 (по замечанию ревьювера). Добавлено обязательное версионирование кэша `tools/gamedb.py`: смена версии гарантирует автоматическую пересборку `data/cache/gamedb_records_*` без ручной очистки кэша на машине пользователя.

## Этапы задачи

1. Доработка `tools/gamedb.py`: сохранение `residents`, `bar squads` и связей размещения отрядов в городах, инкремент версии кэша и тест автоматической инвалидации устаревшего кэша `data/cache/gamedb_records_*`. Готово: тесты подтверждают сохранение ссылок `residents` и `bar squads` для `TOWN` и корректную пересборку кэша. Принят.
2. Доработка `tools/converter_worker.py` и `tools/world_context.py`: проброс `template_sid` у `characters[]` и сопоставление `unique_npcs[].handle` с персонажами отряда со строгой валидацией полноты `handle` (неполный `handle` даёт `unresolved`). Готово: у всех уникальных персонажей отряда в `current.json` доступен `template_sid`, неполные `handle` не вызывают ложных совпадений. Принят.
