# 05-defect-remediation

Статус задачи: завершена 2026-11-11

## Цель

Устранение дефектов действующей реализации `unique_entities_registry`, табличной выгрузки `unique_entities.csv` и конвейера доставки `deliver_companion` по результатам независимой архитектурной ревизии:
1. **P1 — Разделение зачистки локации и состояния босса**:
   - Перенос отметок `cleared` из `locations_progress.json` в `location_link` связанных локаций (`location_link.cleared_evidence`), а не в статус поражения персонажа.
   - Исключение ложного приписывания победы/поражения персонажам (включая Агну в Башне Жестокости, находящуюся в отряде игрока со `state_code: 1`).
   - Требование персонального подтверждения события через таймлайн (`[npc_sid=...]`) для победы/плена/смерти; исключение вывода этих фактов из `location.cleared`, `state_code` или `player_defeat_flag`.
   - Исключение произвольного выбора первой локации при 1:N связях.
2. **P1 — Исправление семантики статуса Мейто**:
   - Разделение двух ортогональных измерений: наблюдаемое наличие (`observation_status`: `observed` / `not_observed`) и происхождение (`provenance_status`: `confirmed_trophy` / `unconfirmed`).
   - Модели без экземпляров не отображаются как найденные у игрока.
   - Крест паладина (`52299-rebirth.mod`) отображается как наблюдаемый экземпляр у Гриффина при отсутствии события трофея в таймлайне.
   - Исторически подтверждённый трофей может отсутствовать в текущем инвентаре без утраты свидетельства.
3. **P1 — Согласование JSON и CSV после доставки**:
   - Единый источник данных: `unique_entities.csv` в доставленном выпуске строится на основе окончательного обогащённого `unique_entities_registry.json`.
   - Для строк `boss` в CSV динамические поля (`state_code`, `squad_status`, `character_id`) заполняются согласованно со строками `npc`.
   - Согласованность данных Великого шамана, Агну и Мейто между JSON и CSV после доставки.
4. **P2 — Исправление разрешения основной локации**:
   - `primary_location_instance_id` назначается только при обоснованной однозначности (все связи указывают на один `instance_id`).
   - При связях более чем с одним `instance_id` (43 NPC в контрольном выпуске) статус равен `ambiguous`, произвольный выбор первого элемента исключён.
   - Статическое местоположение владельца Мейто не принимается за текущее местоположение оружия.
5. **P2 — Уточнение классификации боссов**:
   - Разделение технического признака включения (`classification_origin`: `game_bounty`, `world_state`, `meitou_holder`, `custom_catalog`) и предметной классификации (`category`: `boss`, `world_leader`, `significant_npc`, `recruit`, `unique_npc`).
   - Любой `game_bounty` (< 10000) или `world_state` не считается достаточным для статуса `boss`.
   - Выделена категория `significant_npc` для значимых NPC, не являющихся боссами.
6. **P2 — Защита ручного прогресса при ошибке доставки**:
   - Невалидный `locations_progress.json` не приводит к замене подтверждённых отметок пустыми данными в доставленном реестре.
   - Доставка зависимых производных данных (`location_registry.json`, `unique_entities_registry.json`, `unique_entities.csv`) блокируется, существующие валидные файлы в клоне не затираются.
   - Статус доставки помечается как `degraded`.
7. **Контракты и схемы**:
   - Миграция на версию формата `kenshi-unique-entities-registry/2` с сохранением валидности и обратной совместимости чтения `/1`.
   - Актуализация схем, примеров, тестов и документации.

## Решения

- 2026-11-11. Принят переход на контракт `kenshi-unique-entities-registry/2` в связи с разделением ортогональных статусов Мейто (`observation_status` и `provenance_status`) и переносом зачистки локации в `location_link.cleared_evidence`.
- 2026-11-11. Для NPC с несколькими городами (например, Хамут в 5 городах) `location_resolution` устанавливается в `ambiguous`, а `primary_location_instance_id` равен `null`.
- 2026-11-11. При невалидном `locations_progress.json` доставка зависимых производных файлов (`location_registry.json`, `unique_entities_registry.json`, `unique_entities.csv`) пропускается с сохранением существующих версий в клоне, а общий статус выставляется в `degraded`.
