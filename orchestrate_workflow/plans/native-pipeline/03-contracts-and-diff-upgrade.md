# 03-contracts-and-diff-upgrade

## Цель

Формализация схемы данных `kenshi-session/11` как строго аддитивного расширения `kenshi-session/10`, обновление валидаторов `contracts/` и адаптация детерминированного `tools/diff.py` для отслеживания изменений дипломатии, мировых событий, работ персонажей и складских остатков баз по устойчивым ID.

## Решения

- 2026-11-02. `kenshi-session/11` аддитивно вводит опциональные блоки `diplomacy`, `world_state`, `jobs`, `carrying`, `bounties`, `base_infrastructure` без удаления или изменения существующих полей `kenshi-session/10`. Старые снимки `v10` валидируются и сравниваются без модификаций.
- 2026-11-02. В `tools/diff.py` новые категории регистрируются в `TRACKED`:
  - `diplomacy`: отслеживание изменения отношений с порогом (например, $\Delta \ge 1$ единицы) по `faction_sid`.
  - `world_state`: отслеживание смены состояния лидеров (свободен $\to$ пленён $\to$ мёртв) и городов (статус `replacementTown`).
  - `base_storage`: отслеживание изменения запасов ресурсов на базах игрока по `(town, building_id, item_sid)`.
  - `jobs`: отслеживание добавления/снятия постоянных работ персонажей по устойчивому `id`.
- 2026-11-02. Связывание участников и фракций по отображаемым именам категорически запрещено; сравнение ведётся исключительно по стабильным идентификаторам.

## Этапы задачи

1. **Контракт и схемы kenshi-session/11**: Создать JSON Schema для `kenshi-session/11` в `contracts/` и эталонные примеры в `examples/`, сохранив валидность всех существующих `v10` схем и тестов `check-schemas`. Готово: валидатор принимает оба формата без замечаний. Не начат.
2. **Расширение детерминированного diff**: Внедрить в `tools/diff.py` обработку новых категорий с корректным поведением `not_compared` при отсутствии данных в старых снимках. Готово: табличные unit-тесты в `tests/test_diff.py` подтверждают детерминизм и отслеживание смены отношений фракций и захвата лидеров. Не начат.
3. **Регрессионная верификация контрактов**: Прогнать тесты исторической цепочки снимков, подтвердить отсутствие ложных срабатываний и регрессий на данных предыдущих глав кампании. Готово: `test_diff.py` и `test_contracts.py` зелёные. Не начат.
