# Чат-ИИ модели (LLM ассистенты) как интерфейс кампании

## Основной сценарий

В чат-ИИ ассистенте (ChatGPT, Claude, Gemini и др.) создаётся проект Kenshi с короткими инструкциями из `prompts/03-CHATGPT-INSTRUCTIONS.md`. Межсессионная авторская история хранится в четырёх Markdown-файлах каталога `Campaign/Хроники Хот Лон/` в GitHub. После успешной локальной сверки агент доставляет проверенный выпуск в GitHub по регламенту `README.md` и постоянному разрешению из `AGENTS.md`. Для каждой новой игровой сессии чат-ИИ модель должна прочитать **актуальный** `published/manifest.json` через реально доступное подключение GitHub и загрузить нужные `brief.md/current.json/changes.json` с того же commit. При необходимости обращаться к `squad.md` и подтверждённым событиям. Ручной перенос пакета — резервный способ при недоступности подключения. По явному запросу на изменение постоянных документов игровой Chat может записать их в GitHub и проверить удалённый результат. Это не означает доступ к локальному сейву или обновление Project Sources. Запись в генерируемый `published/` из игрового чата запрещена.

## Постоянные документы

- `Campaign/Хроники Хот Лон/Kenshi_Хроника.md` — установленные события.
- `Campaign/Хроники Хот Лон/Kenshi_Отряд.md` — история персонажей и утверждённые билды.
- `Campaign/Хроники Хот Лон/Kenshi_Текущая_арка.md` — контрольная точка и открытые решения.
- `Campaign/Хроники Хот Лон/Kenshi_Режимы_и_методика.md` — режимы ответа и методика анализа.

Читай постоянные файлы из актуального Git-коммита, не смешивая разные редакции. При явном обновлении измени их на месте и проверь удалённый результат. Для числовых данных используется отдельно проверенный commit публикации с `published/manifest.json`. GitHub-редакция не обновляет автоматически локальные файлы или Project Sources.

## Важно о доступе

- Наличие repo в GitHub не означает автоматическую загрузку в текущий чат или Project Sources. Проверить разрешения и конкретные функции подключения.
- Локальная запись файла и память Codex не являются операцией обновления Project Sources или Library. Общие источники обновляются через поддерживаемый интерфейс записи с последующей проверкой; нельзя выдавать локальную копию за сохранённый облачный источник. Для числового состояния штатным каналом остаётся GitHub.
- Не утверждать актуальность, пока не подтверждены `snapshot_id`, `source_sha256` и (когда доступен) Git commit.
- Если чат-ИИ модель не прочитала `manifest.json` или видит устаревший файл — указать ограничение и предложить перезагрузку источника / ручную загрузку артефактов. Не использовать память чата вместо данных сейва.
- Непрерывное «живое» обновление без нажатия не входит в MVP.

## Представления

1. Сводка: день, время, деньги, численность, текущее положение (только если доказано), важные изменения, активный план.
2. Отряд: сгруппированная таблица по уникальному ID, имени, расе, роли, навыкам и экипировке, только доступные данные.
3. Прогресс: изменения навыков по `changes.json` c явными from/to и отметкой валидности diff.
4. Таймлайн: `confirmed` и `observed` с точной атрибуцией; `inferred` показываются как гипотезы, не попадают в фактическую хронику.
5. Следующий маршрут: рекомендация на основе фактов и явно обозначенных гипотез; игровых карт и лора может не быть в bundle.

## Обратная связь

Чат-ИИ модель может подготовить структурированное предложение события или плана, но не изменять `current.json`. Запись событий лучше выполнять отдельным подтверждённым импортом; интерфейс покажет пользователю, что запись **предложена**, а не сохранена, если инструмент публикации недоступен.

В MVP достаточны обычные Markdown-таблицы и поддерживаемые визуальные элементы. Интерактивный постоянный сайт — отдельная оценка после завершения P0.
