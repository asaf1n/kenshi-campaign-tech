# ChatGPT как интерфейс кампании

## Основной сценарий

В ChatGPT создаётся проект Kenshi с короткими инструкциями из `prompts/03-CHATGPT-INSTRUCTIONS.md`. Для каждой новой игровой сессии ChatGPT должен загрузить **актуальный** `published/manifest.json` и указанные в нём `brief.md/current.json/changes.json` через реально доступное подключение GitHub или через загруженный пакет. При необходимости обращаться к `squad.md` и подтверждённым событиям. Запись в repo из чата — P1, необязательна.

## Важно о доступе

- Наличие repo в GitHub не означает автоматическую загрузку в текущий чат или Project Sources. Проверить разрешения и конкретные функции подключения.
- Не утверждать актуальность, пока не подтверждены `snapshot_id`, `source_sha256` и (когда доступен) Git commit.
- Если ChatGPT не прочитал `manifest.json` или видит устаревший файл — указать ограничение и предложить перезагрузку источника / ручную загрузку артефактов. Не использовать память чата вместо данных сейва.
- Непрерывное «живое» обновление без нажатия не входит в MVP.

## Представления

1. Сводка: день, время, деньги, численность, текущее положение (только если доказано), важные изменения, активный план.
2. Отряд: сгруппированная таблица по уникальному ID, имени, расе, роли, навыкам и экипировке, только доступные данные.
3. Прогресс: изменения навыков по `changes.json` c явными from/to и отметкой валидности diff.
4. Таймлайн: `confirmed` и `observed` с точной атрибуцией; `inferred` показываются как гипотезы, не попадают в фактическую хронику.
5. Следующий маршрут: рекомендация на основе фактов и явно обозначенных гипотез; игровых карт и лора может не быть в bundle.

## Обратная связь

ChatGPT может подготовить структурированное предложение события или плана, но не изменять `current.json`. Запись событий лучше выполнять отдельным подтверждённым импортом; интерфейс покажет пользователю, что запись **предложена**, а не сохранена, если инструмент публикации недоступен.

В MVP достаточны обычные Markdown-таблицы и поддерживаемые визуальные элементы. Интерактивный постоянный сайт — отдельная оценка после завершения P0.
