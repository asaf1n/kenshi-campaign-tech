# Архитектурные границы

## Цепочка

```text
Kenshi saves / screenshots  [read-only; local]
        |
existing converter / extractor (inspect before replacing)
        |
legacy exports (kenshi-session/10 + kenshi-session-diff/5)
        |
normalizer + validator + compatible diff (deterministic)
        |
immutable snapshots / comparable branches + events ledger
        |
atomic publisher -> published/{manifest.json,current.json,changes.json,brief.md,squad.md}
        |
Git (only approved files; push on explicit permission) / manual transport fallback
        |
ChatGPT: load version -> render analysis -> propose plans and event additions
```

Никакой сервисный процесс на постоянном сервере не требуется. Среда Antigravity/Codex/Claude управляет разработкой и запуском локального кода, **не становится** runtime-зависимостью чтения сейва.

## Владение данными

| Область | Автор изменений | Потребитель | Политика |
|---|---|---|---|
| `raw/` и рабочие сейвы | Kenshi, пользователь | конвертер | read-only, не в Git |
| исходные exports | существующий конвертер | normalizer | неизменяемые входы, фиксировать хеш |
| `data/snapshots/` и `data/diffs/` | детерминированный pipeline | publisher | менять только инструментами, иммутабельность исторических снимков |
| `timeline/events.jsonl` | подтверждённые записи пользователя/импорт | publisher и ChatGPT | append-only по event ID; изменение — отдельное корректирующее событие |
| `sessions/` | пользователь/ChatGPT через подтверждённый импорт | planner/summary | планы и результаты без подмены игровых фактов |
| `published/` | publisher | GitHub/ChatGPT | полностью генерируемый release bundle, предыдущий успешный release не портить |
| `docs/`, `contracts/` | разработчик и reviewer | все | изменения контрактов — через независимую проверку |

## Развилки и сравнение

- Один игровой сеанс может иметь несколько сохранений; session_id != snapshot_id.
- Каждый snapshot должен иметь уникальную идентичность исходного входа и допустимого родителя. Время файла само по себе не доказывает игровую последовательность.
- При загрузке раннего сейва формируется отдельная ветка либо явная связь с родителем; сравнивать только выбранные пары.
- Отсутствие поля означает «не получено», а не ноль. Невалидный diff не должен выглядеть как «изменений нет».

## Доступ ChatGPT

- Облачный ChatGPT не читает локальную папку без поддерживаемого механизма соединения. `Project Sources` не являются двусторонней ФС.
- Выходной bundle должен быть небольшим, самодостаточным и пригодным для чтения как в GitHub, так и после ручной загрузки в чат.
- В запросах ChatGPT всегда указывать идентификатор и дату опубликованного снимка. Если загрузка не удалась — явная ошибка актуальности.
- Запись обратно в репозиторий — отдельная опциональная функция, не предполагать её наличие по факту чтения.

## Выбор инструментов

Для вычислений использовать простые Python-скрипты и файлы; переиспользовать существующую реализацию прежде чем добавлять зависимости. Стек (venv, pytest, packaging) определить после аудита реального конвертера. Параллельные агенты работают с независимыми задачами или worktree; один автор на раздел данных и контракта.

## Реализованная граница extract

`python -m tools.campaign extract` → `tools.config.Config` → `tools.extraction.extract` → нормализация → неизменяемый каталог снимка. Для `export` читаются только исходный JSON и проектные файлы, игра/конвертер не запускаются. Для `save` адаптер запускает `python -I -B tools/converter_worker.py`, передавая конфигурацию через UTF-8 JSON в stdin. Рабочий каталог процесса, `session_export.CACHE_DIR` и перенаправление поиска pycache находятся в `.extract-*` под выходным корнем. После завершения временный каталог удаляется.

Внешние `session_export.build_snapshot`, `saves.read_quick_save`, `kenshi_gd.read_file`, `gamedb.load_index` переиспользуются. `session_export.run` и его publisher не вызываются. `collect_stable` заменён прямым `collect`: автоматический повтор на изменившемся источнике не скрывает изменение между проверками SHA-256. До запуска проверяются quick.save и активные platoon; после — исходники конвертера, прочитанные моды и весь сейв. Неизвестные sid остаются диагностикой. Внешние формулы характеристик и их точность не изменяются.

Доступны переданные конвертером состав, ID, принадлежность отрядам, позиция, характеристики, навыки, здоровье, экипировка, протезы, инвентарь, снабжение, время/деньги мира, исследования и собственность. Доступность конкретного поля зависит от источника и модов; отсутствие поля и пустой список различаются. `ps:*` использует portrait_serial; `h:*` — запасной handle с ограниченной устойчивостью. Географическое разрешение координат, события из diff и независимая сверка показателей с UI в этот этап не входят.

Выход, staging и кэш проверяются после нормализации `Path.resolve`, включая junctions: запрещено пересечение с источником, корнями сейвов, конвертером, игрой и Workshop, в обе стороны вложенности. Внутренние ссылки в сейве отвергаются. Python audit hook дочернего процесса разрешает запись только в его временную папку и блокирует внешние процессы, создание ссылок, сеть и новую загрузку native-библиотек. Зафиксированная запрещённая попытка приводит к отказу даже если конвертер перехватил исключение. Это защита от файловых побочных эффектов используемого Python-кода, не полноценная OS sandbox для недоверенного произвольного native-кода. Права оригинальных файлов не меняются.

`current.json` и `provenance.json` сначала создаются в `.snapshot-*` на том же томе; готовый каталог регистрируется переименованием. Входы и метаданные проверяются до регистрации. Существующий ID сравнивается побайтово, не переписывается. Прерывание процесса до регистрации может оставить только временный каталог, не признанный снимком. Протокол восстановления `published/` и общий реестр веток не реализованы в extract.

Независимые проверки используют `unittest` и временные данные. `tests/check_converter.py` выполняет настоящую интеграцию парсера на синтетическом GameData; `tests/check_live.py` принимает явно указанный реальный вход, запускает CLI дважды и сохраняет хеши/коды/время. Синтетическая интеграция не заменяет приёмку на двух реальных сейвах. Команды и переменные окружения приведены в `README.md`.
