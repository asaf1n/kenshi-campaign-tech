# Публикация скриншотов Kenshi и визуальный контекст чат-моделей

## 1. Назначение и концепция

Скриншоты игры Kenshi формируют хронологическую визуальную ленту игрового процесса для сопровождения кампаний чат-моделями (ChatGPT, Claude, Gemini).

**Ключевые принципы:**
- Скриншоты служат **визуальным контекстом**: по ним можно описывать наблюдаемое, но нельзя автоматически подтверждать причины, последствия и игровую хронику.
- Визуальный анализ возможен только когда инструмент чат-модели действительно предоставляет содержимое изображения, а не одну ссылку или метаданные.
- Модуль публикации выступает **техническим экстрактором визуальных данных**: он вычисляет файловые метаданные (SHA-256, mtime), перцептивные хэши (dHash), группирует серии похожих кадров и выполняет технический OCR текста интерфейса.
- **Исключены любые эвристические и генерируемые описания игровых сцен, действий и событий.** При отсутствии результата распознавания сохраняется строгая неопределенность (null или пустой список). Интерпретация происходящего полностью принадлежит LLM-компаньону, работающему с оригинальными кадрами.
- Исходный игровой каталог скриншотов является **строго read-only**. Запрещено любое изменение, удаление или переименование оригиналов в `Kenshi/_screens`.

---

## 2. Источник и конфигурация

- **Стандартный каталог игры**: `<KENSHI_DIR>/_screens` (например, `C:\Program Files (x86)\Steam\steamapps\common\Kenshi\_screens`).
- **Переопределение источника**: переменная окружения `KENSHI_SCREENS_DIR` либо аргумент командной строки `--screens-dir`.
- **Поддерживаемые форматы**: `JPG`, `JPEG`, `PNG` (регистронезависимо).
- **Защита целостности**: файлы нулевого размера, файлы с повреждёнными сигнатурами (magic bytes) и файлы, находящиеся в процессе записи игрой в момент публикации, автоматически отбрасываются.

---

## 3. Политика 7-дневного скользящего окна

При каждом запуске публикации конвейер:
1. Вычисляет границу окна: `cutoff = now - 7 × 24 часа` в UTC.
2. Отбирает все изображения с временем изменения `mtime >= cutoff` (пограничное время ровно 7 суток включается).
3. Кластеризует кадры по времени и dHash, отбирает 20–30 ключевых кадров (по эпизодам, затем равномерно по времени), уменьшает все кадры окна до 1600 px в локальный архив `data/screenshots_archive/` (вне git) и публикует только ключевые.
4. Исключает из новой публикации изображения старше 7 суток.
5. При ошибке чтения каталога публикация отменяется с сохранением предыдущей версии (защита от ошибочного удаления).
6. Если каталог существует, доступен и пуст, публикуется пустой индекс, а ранее опубликованные файлы очищаются.

## 5. Доступ чат-моделей к изображениям

`published/screenshots/index.json` содержит метаданные и ссылки, `index.md` — хронологическую галерею, `feed.md` — техническую ленту серий, а `annotations.jsonl` — структурированные технические факты и OCR. GitHub показывает изображения в своём интерфейсе; доступны ссылки вида:

- Raw URL: `https://raw.githubusercontent.com/asaf1n/Kenshi-Compain/main/published/screenshots/<filename>`.
- Страница GitHub: `https://github.com/asaf1n/Kenshi-Compain/blob/main/published/screenshots/<filename>`.
- Относительное изображение в `index.md` и `feed.md`: `![filename](filename)`.

Наличие ссылки и возможность просмотра в браузере **не гарантируют**, что конкретный чат ChatGPT, Claude или Gemini сможет получить и проанализировать бинарное изображение. Возможность зависит от подключённого инструмента и интерфейса; проверяй её для каждого используемого клиента. При недоступности изображения модель может использовать индекс и разметку как метаданные и должна прямо обозначать ограничение.

Время `modified_at` — время изменения файла, не игровая дата. Порядок файлов не доказывает причинно-следственную или игровую хронологию.

## 6. Технический экстрактор и хронологическая лента

Публикация скриншотов формирует два производных артефакта:
- `published/screenshots/annotations.jsonl` — технический JSONL-экстракт каждого кадра по схеме `kenshi-screenshot-annotation/1` для программного поиска серий, локаций, участников и диалогов по фактам OCR.
- `published/screenshots/feed.md` — техническая хронологическая лента сгруппированных серий кадров со ссылками на опубликованные кадры и распознанными данными UI.

Аннотации, лента `feed.md` и галерея `index.md` публикуются только при содержательном OCR (непусто хотя бы одно поле `ocr`); при пустом OCR остаётся `index.json`. При доставке в игровой репозиторий файлы `published/screenshots/`, которых нет в текущей публикации, удаляются; каталоги вне `published/screenshots/` не затрагиваются. Если в публикации нет каталога `screenshots/`, целевой каталог не изменяется.

### Принципы обработки:
1. **Двухуровневая дедупликация**:
   - *Точные дубликаты*: файлы с идентичным SHA-256 помечаются `is_exact_duplicate = True`, `duplicate_of = <sha256_оригинала>`.
   - *Похожие кадры / серии*: последовательные кадры с малой временной разницей ($\Delta t \le 180$ сек) и близким перцептивным разностным хэшем (dHash, расстояние Хэмминга $\le 14$) объединяются в единую техническую серию (`seq_XXX`).
2. **Кэширование по SHA-256**: Неизмененные скриншоты не переобрабатываются повторно.
3. **Технический OCR интерфейса**:
   - При наличии `GEMINI_API_KEY` и сетевой доступности выполняется только распознавание текста интерфейса (OCR дня, времени, зоны, реплик диалогов, уведомлений). Генерация описаний сцен, действий и сюжета запрещена на уровне промпта и схемы.
   - При отсутствии сети или исчерпании лимитов срабатывает встроенный Circuit Breaker и сохраняется чистый метаданный экстракт (`provenance.source = "metadata"`) с `null` для нераспознанных полей.
4. **Изоляция сбоев**: Любые ошибки процесса извлечения изолируются и не блокируют публикацию проверенного состояния сейва и оригинальных скриншотов.

## 7. Команды запуска

```powershell
# Публикация скриншотов и технической ленты вместе с очередным обновлением состояния
python -m tools.campaign publish

# Публикация с явным указанием источника скриншотов
python -m tools.campaign publish --screens-dir "C:\Kenshi\_screens"

# Автономное извлечение и пересборка feed.md / annotations.jsonl
python -m tools.campaign annotate-screenshots --screens-dir "C:\Kenshi\_screens"

# Проверка схемы реестра и аннотаций скриншотов
python -m tools.campaign check-schemas

# Прогон автоматических тестов скриншотов и экстрактора
python -m unittest tests/test_screenshots.py tests/test_screenshot_annotations.py
```
