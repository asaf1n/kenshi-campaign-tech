# Публикация скриншотов Kenshi и визуальный контекст чат-моделей

## 1. Назначение и концепция

Скриншоты игры Kenshi формируют хронологическую визуальную ленту игрового процесса для сопровождения кампаний чат-моделями (ChatGPT, Claude, Gemini).

**Ключевые принципы:**
- Скриншоты служат **визуальным контекстом**: по ним можно описывать наблюдаемое, но нельзя автоматически подтверждать причины, последствия и игровую хронику.
- Визуальный анализ возможен только когда инструмент чат-модели действительно предоставляет содержимое изображения, а не одну ссылку или метаданные.
- В текущей реализации сборщик не выполняет OCR и смысловую разметку. Это описание реализованного состояния, а не запрет на автоматическую обработку изображений в будущем. Игрок не вводит текстовых описаний при сохранении скриншотов; компаньон может самостоятельно описывать видимое на полученных оригиналах. Автоматическое подтверждение событий и создание фактической хроники из предположений недопустимы.
- Исходный игровой каталог скриншотов является **строго read-only**. Запрещено любое изменение, удаление или переименование оригиналов в `Kenshi/_screens`.

---

## 2. Источник и конфигурация

- **Стандартный каталог игры**: `<KENSHI_DIR>/_screens` (например, `C:\Program Files (x86)\Steam\steamapps\common\Kenshi\_screens`).
- **Переопределение источника**: переменная окружения `KENSHI_SCREENS_DIR` либо аргумент командной строки `--screens-dir`.
- **Поддерживаемые форматы**: `JPG`, `JPEG`, `PNG` (регистронезависимо).
- **Защита целостности**: файлы нулевого размера, файлы с повреждёнными сигнатурами (magic bytes) и файлы, находящиеся в процессе записи игрой в момент публикации, автоматически отбрасываются.

---

## 3. Политика 7-дневного скользящего окна

При каждом запуске публикации конвейер:
1. Вычисляет границу окна: `cutoff = now - 7 × 24 часа` в UTC.
2. Отбирает все изображения с временем изменения `mtime >= cutoff` (пограничное время ровно 7 суток включается).
3. Публикует **все** изображения в пределах окна без ручного отбора в оригинальном разрешении и качестве.
4. Исключает из новой публикации изображения старше 7 суток.
5. При ошибке чтения каталога публикация отменяется с сохранением предыдущей версии (защита от ошибочного удаления).
6. Если каталог существует, доступен и пуст, публикуется пустой индекс, а ранее опубликованные файлы очищаются.

## 4. Структура опубликованного пакета

```text
published/
├── manifest.json
├── current.json
├── changes.json
├── locations.json
├── world_reference.json
├── timeline.jsonl
├── brief.md
├── squad.md
└── screenshots/
    ├── index.json          # Машиночитаемый реестр kenshi-screenshots-index/1
    ├── index.md            # Хронологическая галерея со встроенными превью
    ├── screenshot_393.jpg  # Оригинальные изображения за последние 7 суток
    └── screenshot_394.jpg
```

## 5. Доступ чат-моделей к изображениям

`published/screenshots/index.json` содержит метаданные и ссылки, `index.md` — хронологическую галерею. GitHub показывает изображения в своём интерфейсе; доступны ссылки вида:

- Raw URL: `https://raw.githubusercontent.com/asaf1n/kenshi-campaign-tech/main/published/screenshots/<filename>`.
- Страница GitHub: `https://github.com/asaf1n/kenshi-campaign-tech/blob/main/published/screenshots/<filename>`.
- Относительное изображение в `index.md`: `![filename](filename)`.

Наличие ссылки и возможность просмотра в браузере **не гарантируют**, что конкретный чат ChatGPT, Claude или Gemini сможет получить и проанализировать бинарное изображение. Возможность зависит от подключённого инструмента и интерфейса; проверяй её для каждого используемого клиента. При недоступности изображения модель может использовать индекс только как метаданные и должна прямо обозначать ограничение.

Время `modified_at` — время изменения файла, не игровая дата. Порядок файлов не доказывает причинно-следственную или игровую хронологию.

## 6. Возможное развитие: автоматическая разметка (не реализовано)

Для ускорения игрового сопровождения предлагается дополнительная обработка опубликованных изображений:

- OCR видимого интерфейса: игровой день и время, локация, имена, диалоги, задания и предупреждения, с указанием уверенности и ссылкой на кадр.
- Краткие визуальные теги: присутствующие персонажи, тип сцены (бой, путешествие, база, диалог, инвентарь), различимые объекты и условия.
- Группировка точных дублей по SHA-256 и похожих кадров по perceptual hash, сохраняя варианты со значимыми изменениями интерфейса, текста или сцены.
- Поиск и выбор репрезентативных кадров для ответов компаньона без необходимости просмотра всей недельной ленты.

Все извлечённые признаки — машинные наблюдения, не подтверждённые игровые события. Не восстанавливать сюжетную причинность только по близости кадров и не подменять изображения их описаниями. Текущий контракт публикации всех скриншотов за 7 суток остаётся в силе: удаление похожих кадров из опубликованного набора требует отдельного решения.

## 7. Команды запуска

```powershell
# Публикация скриншотов вместе с очередным обновлением состояния
python -m tools.campaign publish

# Публикация с явным указанием источника скриншотов
python -m tools.campaign publish --screens-dir "C:\Kenshi\_screens"

# Проверка схемы реестра скриншотов
python -m tools.campaign check-schemas

# Прогон автоматических тестов скриншотов
python -m unittest tests/test_screenshots.py
```
