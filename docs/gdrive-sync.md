# Синхронизация с Google Диском

Выгрузка доставляется двумя каналами: GitHub (`deliver-companion`) и локально примонтированный Google Диск. Диск нужен читателям, которые не принимают `.json` по URL и не обходят отдельные `.jpg`: Gemini Notebook (NotebookLM) подключает файлы Диска как источники.

## Корень и раскладка

Корень проекта задаётся `KENSHI_GDRIVE_DIR`. Без переменной проверяются по порядку `G:\Kenshi Compain. Docs`, `G:\Мой диск\Kenshi Compain. Docs`, `G:\My Drive\Kenshi Compain. Docs`. Диск не найден — `WARNING` в stderr и `gdrive.status=skipped`; публикация и доставка в GitHub не прерываются.

Подкаталоги повторяют раскладку `Kenshi-Compain` (константы `GDRIVE_*` в `tools/config.py`):

| Каталог | Назначение | Содержимое |
|---|---|---|
| `published/` | Сессия | `brief.md`, `squad.md`, `changes.md`, `changes.json`, `manifest.json`, `timeline.jsonl`, `screenshots_index.md`, `screenshots_latest.pdf` |
| `published/screenshots/` | Кадры | `index.md`, кадры выпуска и кадры дельты, не вошедшие в выпуск; кадры не удаляются при выходе из окна 7 суток |
| `Campaign/` | Канон | зеркало зафиксированных `*.md` из `Campaign/` репозитория `Kenshi-Compain` с теми же относительными путями; файлы с незакоммиченными правками пропускаются и перечисляются в отчёте, удалённые в репозитории на Диске остаются |
| `tmp/` | Входящие | пакеты модели; принятые переносятся в `tmp/Обработано/` |

## Запись и `file_id`

Drive for desktop связывает `file_id` с файлом. `os.remove`, `unlink` и замена через `os.replace` создают новый документ и разрывают привязку источника в Gemini Notebook. Поэтому `write_in_place` перезаписывает существующий файл открытием на запись и не трогает файл с совпадающими байтами. Запись на месте не атомарна: при обрыве файл может остаться неполным до следующей синхронизации. `manifest.json` записывается последним и только при отсутствии ошибок записи. Если в окне нет кадров, PDF не собирается и на Диске остаётся прежний файл.

## Команды

```powershell
python -m tools.campaign pipeline ... --sync-drive           # после публикации и доставки: сессия и канон
python -m tools.campaign sync-drive [--scope all|session|chronicle] [--gdrive-dir <путь>]
python -m tools.campaign ingest-inbox [--companion-dir <путь>] [--gdrive-dir <путь>]
```

`Initialize-Pipeline.ps1` (хоткей) передаёт `--sync-drive`. В `pipeline` сбой Диска остаётся предупреждением; автономные `sync-drive` и `ingest-inbox` завершаются кодом 1, если синхронизация неполная или пакет отклонён.

## Приём входящих пакетов

`ingest-inbox` запускается только явно: пакет меняет авторские документы. Просматриваются `*.md` и `*.txt` верхнего уровня `tmp/` на Диске и `inbox/` игрового репозитория.

- `=== ФАЙЛ: <путь>.md ===` ... `=== КОНЕЦ ===` — запись файла. Допустимы только `.md` внутри `Campaign/`. Путь без префикса `Campaign/` отсчитывается от единственного каталога кампании. Блок закрывает только `КОНЕЦ`.
- `=== ВЫГРУЗКА S-YYYYMMDD-n ===` — артефакт сессии в `Campaign/<campaign>/archive/sessions/`; кампания берётся из поля `campaign:`. Существующий файл `archive/sessions/S-*` с другим содержимым не перезаписывается никаким блоком.
- `=== СТРОКА ХРОНОЛОГИИ ===`, `=== ПРАВКИ: ... ===` автоматически не применяются и перечисляются в отчёте в поле `manual`, а имя перенесённого пакета получает суффикс `-manual`.

Пакет применяется целиком: отсутствие завершающего `=== КОНЕЦ ===`, недопустимый путь, неизменяемый артефакт, незакоммиченные правки в целевом файле или сбой записи отклоняют его, записанное откатывается, файл остаётся во входящих. Цель с совпадающими байтами считается применённой. Файлы без маркеров игнорируются. Команда не коммитит: изменения проверяются и фиксируются в игровом репозитории отдельно. Принятый пакет получает штамп времени UTC в имени.
