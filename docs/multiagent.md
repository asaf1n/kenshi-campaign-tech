# Использование Antigravity и прежнего мультиагентного workflow

## Проверенные исходные положения

Репозиторий `asaf1n/AI-Orchestrated-Workflow`, ветка `main` (проверен на коммите `acd88df32f035cf0416d15a95204d895555b6881`), содержит навыки `orchestrate`, `planner`, `implementer`, `reviewer`, `AGENTS.md`, `CLAUDE.md` и проектные примеры. Общий протокол уже определяет `spec.md` / `result.md` / `review.md`, отдельный план и сессии, независимый reviewer, коммиты после приёмки и запрет push без разрешения. Эти определения — внешний источник истины; они **не дублируются** здесь.

## Предпочтительное назначение

| Роль | Среда | Ответственность |
|---|---|---|
| Orchestrator | Antigravity, если установлен и навык реально обнаружен | инвентаризация, декомпозиция, выбор исполнителя, контроль состояния и приёмки |
| Planner / Architect | Claude Code либо Antigravity | исследование конвертера и данных, план по этапам |
| Implementer | Codex (первый вариант) или Claude Code | Python-реализация, тесты, интеграция |
| Reviewer | Claude Code для изменений Codex; Codex для изменений Claude | независимый review архитектуры, контрактов и данных |
| Runtime | Python/CLI без постоянного LLM | extract/diff/validate/render/publish |

Названия моделей и команды вызова устанавливаются по фактическому runtime. Не считай встроенную модель Antigravity внешним Claude Code. Если Antigravity умеет вызывать Codex/Claude через существующие skills, переиспользуй их и зафиксируй реальный канал; не создавай второй оркестратор поверх него. Docker Agent, дополнительные MCP, собственная шина и сложные субагенты — только при доказанной необходимости.

## Порядок работы

1. Чтение текущего состояния, контракта проекта, рабочего дерева и установленных skills; существующие локальные наработки сохраняются.
2. Независимые исследования допустимы параллельно: формат сейва/экспортёра и интеграция ChatGPT. Изменения файлов проекта — один назначенный владелец на область.
3. Planner создаёт план с P0-задачами, критериями и доказательствами. Независимый reviewer проверяет план, пользователь утверждает.
4. Каждый этап: spec → implementation → tests → result → independent review → acceptance. Критические исправления повторно ревьюятся.
5. Коммит принятого этапа делает orchestrator; push только по разрешению пользователя.
6. Итог: подтверждённые результаты, таблица AC-01…15, оставшиеся риски и команды повторного прогона.

## Пропорциональность

Не запускать многоагентную схему для генерации одного Markdown или простого исправления линтера. Полноценное независимое ревью обязательно для изменения схем и логики diff/identity/branch, чтения бинарных save, публикации и миграции legacy. Не использовать историю прошлых чатов как источник фактического состояния файлов.

## Начальная привязка

`orchestrate_workflow/method.md` содержит только пути проекта и предметные отклонения. Протокол установленных навыков остаётся внешним. Если в текущем Antigravity нет глобального `orchestrate`, следовать проверенной средой процедуре ручного исполнения утверждённого плана вместо создания фиктивного вызова.
