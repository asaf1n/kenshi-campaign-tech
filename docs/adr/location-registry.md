# Реестр локаций кампании

Решение принято 2026-11-08 по заданию игрока. Конвертер вычисляет факты, компаньон хранит подтверждённые отметки игрока, карта отображает итог.

## Исходные данные

На момент обследования удалённые `main` указывали на `234c1bc` в `kenshi-campaign-tech` и `c01927c` в `Kenshi-Compain`. В локальном индексе 122 снимка и две ветки. Из 537 файлов `data/locations/` к цепочке Day 135 10:49 относятся 24, начиная с Day 131 15:06. Для всех 24 есть разрешение локаций. `in_location` даёт пять объектов. Скуин и Ровная лагуна имеют свидетельства присутствия и собственности. Деревня Серодёров, Улей и Хаб имеют свидетельства собственности. Пурпурные пески в этих данных фигурируют как регион.

Бинарные записи `Town state` (тип 94) в `quick.save` содержат логическое `discovered` и строковый `instance`. Полный хеш каталога `quicksave` совпал с `source_sha256` выпуска Day 135 10:49. Из 554 записей по `instance` однозначно сопоставлены 261 из 261 локации, из них 179 с `discovered=true` и 82 с `false`. В сохранениях `hot lon 9` (Day 26 14:29) и `hot lon 10` (Day 27 02:53) флаг Ровной лагуны меняется с `false` на `true`, а число персонажей с `in_location` в ней растёт с 0 до 12. У Ancient Labs флаг тоже меняется на `true`, при этом игровое `explored` остаётся `false`. Сравнение выполнено чтением сейвов и штатным разрешением координат. Издатель также различает обнаружение поселений в [архиве примечаний к версиям](https://lofigames.com/patch-notes/).

`fcs.def` определяет ссылку `TOWN.refs.faction` на `FACTION`. Слияние исходных игровых записей даёт одну ссылку для 260 из 261 локации. Шаблон Ghost Village содержит две. Реестр публикует однозначную шаблонную фракцию по игровым файлам справочника. Эта фракция характеризует шаблон. Текущее владение поселением в ходе кампании может отличаться.

## Слои и доставка

`publish` строит `published/location_registry.json` (`kenshi-location-registry/1`) с одной записью на `instance_id` справочника выпуска. Обход начинается с публикуемого снимка и следует по `parent_snapshot_id`. Боковые ответвления исключаются. При регрессии игрового времени поздние снимки за границей отката исключаются, общие предки сохраняются. `presence` содержит первую и последнюю фиксации персонажей в порядке цепочки, `property` — последнюю фиксацию собственности. В обоих случаях требуется `in_location`. Отсутствующие разрешения уменьшают покрытие. Если родитель указан, но цепочка недоступна, `coverage.chain_incomplete` отмечает ограничение. Повреждённая цепочка индекса прерывает публикацию. `discovered` относится к текущему снимку и не меняет автостатус. Для старого снимка конвертер может прочитать это поле из точного сейва после проверки хеша до и после чтения. Снимок остаётся неизменяемым.

`Campaign/Хроники Хот Лон/locations_progress.json` (`kenshi-location-progress/1`) содержит только подтверждённые отметки. Ключ записи состоит из `branch_id` и `instance_id`. Валидатор сверяет кампанию, существование ID и дубли. Текущий файл должен сохранять ранее зафиксированные отметки и их максимальные статусы по основной линии истории Git. При смене `world_ref_id` совпавшие ID применяются напрямую. Старые несопоставленные записи остаются в ручном файле для аудита и не влияют на итог. Новые отметки требуют ID из справочника выпуска. Применяются отметки текущей ветки, датированные отметки позже выпуска отсекаются. Отметка без времени действует в пределах указанной ветки.

После подготовки клона `deliver-companion` проверяет ручной файл до записи выпуска и вычисляет `max(auto_status, ручной статус)` по порядку `no_evidence < visited < explored`. При равенстве приоритет у автостатуса. Локальный технический выпуск содержит автостатусы. Итоговый файл игрового репозитория содержит источник статуса. Карта читает заявленный в манифесте реестр и может применить более свежую отметку текущей ветки. Старые выпуски остаются читаемыми, секретность следует политике карты. Ретроспективное заполнение отметок выполняется отдельно.
